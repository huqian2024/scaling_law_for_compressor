## 1. 计算平台与约束

```text
两套计算资源，职责不重叠:

CFD 计算     师兄的独立服务器
             网格、边界条件、工况、求解、收敛检查、任务调度
             本地不实现、不管理、不猜测

AI 训练      本人的 GPU HPC 平台（Slurm 调度）
             训练、验证、checkpoint、结果汇总
```

```text
GPU HPC 的现实约束（决定流程设计）:
  存在任务额度 / 调度优先级限制；
  额度紧张时可能进入慢速队列，排队时间不可控；
  单作业可能有时间上限（具体数值未知）。

因此流程必须优先减少:
  无效 GPU 占用（训练已经收敛却继续跑）
  重复训练（同样的数据/模型重复提交）
  不必要的 Slurm 作业（大量小作业反复排队）
```

```text
明确不猜测的内容:
  GPU 型号 / 数量、分区名称与限制、账户额度、队列优先级规则、
  单作业时间上限、存储配额
  -> 这些必须在真实平台信息可用后再写入执行文档。
```

```text
由上述约束导出的设计原则（PROPOSED）:
  1) 一个阶段尽量只提交必要的作业，不为每个 N 档位单独排队多次；
  2) 训练过程中定期验证，收敛即停（Early Stopping）；
  3) 作业被时间上限中断时，能从 checkpoint 继续，而不是从头重跑；
  4) 数据更新优先“续训”，但续训结果必须与从头训练分开记录（见 §5.4）。
```

## 2. 渐进式训练流程

### 2.1 主流程

```text
[1] 接收已经完成且通过有效性检查的 CFD 数据
        （只接收 CFD 侧判定为 success 的样本；失败样本记录但不进入训练）
[2] 构建带版本的数据快照  snapshot_vN
        （冻结当时的样本清单、参数、预处理统计量来源、数据集归属）
[3] 当可用训练样本达到适当规模时，启动阶段性训练
        （“适当规模”= PENDING，不在此固定）
[4] 新样本返回后更新训练数据（生成新的 snapshot，不覆盖旧快照）
[5] 视情况选择 checkpoint 续训或者从头训练
        （选择规则见 §5.4；每次必须记录选了哪一种）
[6] 记录每一阶段的训练条件与结果
[7] 最终基于统一协议整理 Scaling Law 实验
```

```text
关键点:
  [3] 允许在数据不完整时开始训练，用于验证流程与早期趋势；
  [7] 只有在协议统一之后，这些阶段性结果才可能进入正式 Scaling Law 分析。
  阶段性结果 != 正式 Scaling Law 结论。
```

### 2.2 训练规模梯度（候选）

| 候选 N | 说明 |
|---:|---|
| 1k | 流程验证 / 早期趋势 |
| 2k | 流程验证 / 早期趋势 |
| 5k | 初步曲线 |
| 10k | 初步曲线 |
| 20k | 主体区间 |
| 35k | 主体区间 |
| 50k | 主体区间 |
| 70k | 高数据量 |
| 100k | 计划上限 |

```text
这组数值来自 2026-10-13 的历史记录，现降级为“候选梯度”：
  不是强制冻结，不再限制后续训练规划；
  可以按实际数据返回速度、GPU 额度与曲线形状调整档位；
  但一旦某个阶段开始对外比较，就必须在记录中写明实际使用的档位。
```

### 2.3 “已完成数量”与“数据集组成”必须分开

```text
CFD 完成数量（随时间增长，受易算程度影响）
      !=
最终冻结的数据集组成（按协议选定的样本集合）

风险: 如果直接“先到先用”，完成快的样本可能集中在容易收敛的参数区域，
      导致训练集分布偏向易算区域，Scaling Law 斜率被这种选择偏差污染。

PROPOSED 缓解方式:
  - 每个快照记录明确的选取规则（例如按 sobol_index 升序取有效样本）
  - 记录每个快照的 sobol_index 覆盖范围与各参数区间的覆盖情况
  - 正式实验前检查快照的分布是否明显偏斜（检查方式 PENDING）
  - 不用“完成时间”作为样本选取依据
```

## 3. 验证集与 Early Stopping

### 3.1 验证集的用途（当前计划）

```text
验证集在当前计划中的主要用途 = Early Stopping、模型选择、减少 GPU Slurm 时间
```

```text
不使用验证集做的事:
  不参与梯度更新
  不用于测试集评估结论
  不把验证集指标当作最终泛化误差 E
```

### 3.2 规划中的机制

```text
定期评估 Validation Loss（频率 PENDING，可按 epoch 或按固定步数）
保存验证性能最优的 checkpoint（best checkpoint，而不是最后一个）
设置可配置的 patience 与 min_delta
依据验证指标决定停止训练
继续训练时恢复：模型权重 + 优化器状态 + 学习率调度状态
记录：训练曲线、最优 epoch、实际优化步数、GPU 时间
支持 Slurm 时间限制下的安全退出与恢复
```

```text
具体数值（全部 PENDING）:
  评估频率、patience、min_delta、学习率调度参数、最大 epoch/步数、
  是否需要多个验证指标、指标聚合方式
本轮只固定“机制存在”，不固定参数。
```

### 3.3 Slurm 时间限制下的安全退出与恢复

```text
PROPOSED 行为要求（尚未实现）:
  1) 训练循环按固定间隔保存 checkpoint（含模型 / 优化器 / 调度器 / 步数 / 随机状态）
  2) 收到 Slurm 时间信号或达到安全余量时，主动写出最后一个 checkpoint 再退出
  3) 退出状态与“训练失败”区分记录（是时间原因还是收敛/错误）
  4) 恢复训练时先校验：数据快照版本、模型结构、优化器参数、起始步数一致
  5) 续训后继续累计 GPU 时间，不把续训作业时间当成独立实验
```

```text
注意: 以上是流程要求，不是已实现的代码。
      本仓库当前没有任何 Slurm 脚本。
```

### 3.4 初期验证样本不足时的处理

```text
允许在验证样本不足时，先使用固定的小规模验证子集：
  - 子集必须固定（不允许每次训练重新随机抽）
  - 子集必须记录版本（validation_snapshot_id / case 列表）
  - 后续逐步扩展为完整验证集
```

```text
正式比较不同模型与训练规模时，尽量使用一致的验证评估基准：
  同一组验证 case、同一预处理版本、同一指标定义；
  若验证集版本不同，必须在结果表中标注，不能直接横向比较。
```

允许:

```

计划规模: 20000 个有效样本（PROPOSED 目标值；由三组独立 Sobol 中的 Test 组提供）
测试集一旦开始正式评估，其组成必须固定并记录版本。
```

```text
当前计划的实际含义:
  “不看测试集”在工程上意味着测试集结果不进入训练循环的任何判断；
  正式评估阶段可以一次性评估并记录，但不据此回头调参后
  再报告同一测试集上的结果。
```

## 5. Scaling Law 实验

### 5.1 研究目标

```text
E = f(N, P)

N : 有效训练样本量（N = usable training case count，定义保留）
P : 模型可训练参数量
E : 在统一评估协议下得到的误差
```

```text
E 的具体数学定义仍未确定（PENDING）：
  场变量列表、单位、归一化、空间/域/场权重、mask、逐 case 聚合、跨 case 聚合、
  插值/网格映射版本、无效样本处理方式
  -> 在这些确定之前，任何“E 的数值”都只能作为阶段性内部结果。
```

### 5.2 每次训练必须记录的字段（PROPOSED 清单）

| 类别 | 字段 |
|---|---|
| 数据 | 数据集快照版本、N、样本选取规则、预处理版本、验证快照版本 |
| 模型 | 模型族（PCA+MLP / U-Net / FNO）、结构、可训练参数量 P、关键超参数 |
| 训练 | 随机种子、损失函数、优化器、学习率调度、batch size、最大预算 |
| 停止 | Early Stopping 规则（patience / min_delta）、最优 epoch、实际优化步数 |
| 初始化 | 从头训练 / 续训 / 其他初始化方式（必须显式标注） |
| 资源 | GPU 类型（平台信息可用后填）、GPU 时间、作业数量、是否被时间上限中断 |
| 结果 | 最佳 checkpoint、验证曲线、验证指标、测试指标（仅在正式评估阶段） |
| 追溯 | 代码版本、配置版本、运行时间、Slurm 作业标识（可用时） |

### 5.3 模型路线（候选，保留）

```text
1) PCA + MLP    （PCA 只在训练集上拟合；P 只计 MLP 可训练参数）
2) U-Net
3) FNO
```

```text
不现在固定: 模型规模网格、层数/通道/宽度/modes、重复次数、损失函数、训练预算。
跨模型族比较时，P 相同不代表算力或表达能力相同
（沿用 SCALING_EXPERIMENT_DESIGN 的原则）。
```

### 5.4 续训与从头训练不能无控制混用

```text
核心限制:
  续训得到的模型与独立从头训练的模型，其优化轨迹和有效训练预算不同；
  两者未经控制不能直接混为同一个 Scaling Law 实验的数据点。

PROPOSED 分层策略:
  开发阶段（省 GPU 时间）:
      允许用 checkpoint 续训推进到更大的 N，用于快速看趋势、验证流程；
      这些结果标记为 DEVELOPMENT / CONTINUATION，不进入正式图。
  正式研究阶段（严格对照）:
      在统一协议下，对选定的 N / P 档位做独立从头训练；
      重复次数、随机种子、预算与评估方式统一；
      只有这一层结果用于对外 Scaling Law 结论。

必须在结果记录中显式写明:
  initialization = FROM_SCRATCH | CONTINUED_FROM_CHECKPOINT | OTHER
  continued_from = <checkpoint 标识 / 阶段 / 数据快照>
  effective_optimizer_steps / effective_epochs
```

```text
推论:
  “续训很省时间”与“续训结果可以替代从头训练”是两件事。
  前者是工程手段，后者是需要实验证据支持的研究问题（PENDING）。
```

## 6. 数据版本与防泄漏

### 6.1 数据集身份

```text
Train / Validation / Test 三个独立数据集身份（分别来自三组独立 Sobol）。
样本不得跨组迁移。
Test 永不进入训练或模型选择流程。
```

### 6.2 三种状态的区分（必须显式记录）

```text
generated            已生成 GeomTurbo
qc_pass              通过几何 QC（geometry_qc_v1_hard）
cfd_success          通过 CFD 有效性检查，可用于训练

只有 cfd_success 的样本才可能进入训练集；
qc_pass 不代表可 CFD，cfd_success 也不代表气动性能“好”。
```

### 6.3 数据快照管理

```text
snapshot_vN 至少记录:
  snapshot_id / 创建时间
  使用的 case 清单（group + seed + sobol_index）
  各状态计数（generated / qc_pass / cfd_success）
  样本选取规则与 sobol_index 覆盖范围
  预处理版本（若已拟合）
  与上一个快照的差异（新增 / 移除 / 变更）

规则:
  新样本 -> 新快照，不原地修改旧快照；
  训练结果必须能追溯到唯一快照；
  旧快照不删除（用于复现与对比）。
```

### 6.4 防泄漏规则（沿用并强化）

```text
- 同一个 case 不得同时出现在 train 与 validation/test；
- 归一化统计量只能从训练集拟合；
- PCA 等需要拟合的预处理只能使用训练集（不得用验证集/测试集）；
- 验证集不得用于测试结论，测试集不得用于任何训练期决策；
- 同一训练规模 N 下，不同模型应尽量使用相同的训练样本；
- 若 CFD 失败导致某样本缺失，替换规则必须记录（不得静默替换）；
- 几何层面的重复（不同 seed 产生相同/近似几何）若发现，
  需按组内去重规则处理并记录。
```

```text
以上只提出接口、元数据与实验原则，不要求立即实现数据管理代码。
```
